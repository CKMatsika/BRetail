# Payroll setup API

Endpoints require authenticated tenant context and an enabled Payroll module.

The reporting, payslip-rendering and payslip-email routes below are authenticated web routes, not versioned `/api/v1` endpoints.

- `GET /api/v1/payroll` — lists authorized rule versions, visible employees and compensation terms only when the caller has compensation view permission.
- `POST /api/v1/payroll/rules` — creates a draft rule version. Required fields include currency, effective dates, ordered PAYE bands, AIDS levy percentage, source name and source URL. NSSA fields are nullable.
- `PATCH /api/v1/payroll/rules/{id}/approve` — independently approves a draft rule version. The preparer cannot approve their own rule; overlapping approved periods are rejected.
- `POST /api/v1/payroll/employees/{employeeId}/compensation` — creates a confidential monthly salary term for a visible employee, including recurring cash earnings. Effective dates may overlap across USD and ZWG terms, but not within the same currency.
- `POST /api/v1/payroll/runs` — creates an immutable monthly calculation draft for a visible branch, currency, and `YYYY-MM` period. USD or ZWG runs require an approved rule set covering the month and salary terms that continuously cover each employee's employed dates in one currency. Hires, departures and mid-month term changes require an approved sourced daily PAYE rule. Optional single-currency `adjustments` rows contain `employee_id`, `kind`, `description` and positive `amount`; supported kinds are `cash_earning`, `taxable_benefit`, `allowable_deduction`, `tax_credit` and `cash_deduction`.
- Mixed runs use `currency: "MIXED"` and require `payment_date: "YYYY-MM-DD"`, continuous USD and ZWG compensation-term coverage for each employed day (zero-valued terms are allowed), an approved USD rule set for the period, and an approved applicable ZWG FX rate for the payment date. Partial employment and mid-month salary changes require sourced calendar-day USD PAYE bands. Optional mixed-run `adjustments` rows use the same fields as the single-currency rows plus `currency: "USD"|"ZWG"`. If NSSA coverage is confirmed, the USD rule must also have verified NSSA rates and the applicable USD ceiling; eligibility must remain stable across the covered terms. The USD tax rule calculates aggregate converted taxable income, then PAYE is allocated in proportion to each currency's converted taxable income. NSSA is calculated against converted combined cash wages and the approved USD ceiling, then allocated between currencies by each currency's share of converted cash wages. Line snapshots retain native amounts, salary-term segments and rate IDs; run and line total fields are USD equivalents.
- `PATCH /api/v1/payroll/runs/{id}/approve` — approves a draft as a different user from its preparer; the calculation then cannot be edited.
- `POST /api/v1/payroll/runs/{id}/post` — posts an approved run to the existing journal workflow. Single-currency payroll must equal the company ledger currency. Mixed payroll converts its USD-equivalent totals to the USD or ZWG company base currency using the saved actual-pay-date FX snapshot; the accounting period must be open.
- `POST /api/v1/payroll/runs/{id}/reverse` — posts a reasoned reversing journal for an existing payroll posting; a corrected calculation can be drafted after reversal.
- `POST /api/v1/payroll/runs/{id}/settle` — records the full net-wage bank payment after the transfer is made. Requires `payroll.runs.settle`, an active matching bank account and sufficient recorded funds. Mixed settlement may use the base-currency bank account and a matching foreign bank account for the other currency; its foreign-ledger decrease clears the base-currency wage liability using the saved FX snapshot. Retries use `request_key`.
- `GET /payroll/runs/{id}/register` — downloads an approved run's CSV register; requires export and compensation view permissions.
- `GET /payroll/ytd?year=YYYY` — downloads employee year-to-date totals for approved, non-reversed payroll runs; requires export and compensation view permissions.
- `GET /payroll/returns/monthly?period=YYYY-MM&branch_id={id}` — downloads a TaRMS reconciliation workpaper with branch/currency summary and employee detail from approved, non-reversed runs; requires export and compensation view permissions. It is not an electronic filing.
- `GET /payroll/runs/{runId}/lines/{lineId}/payslip` — renders a confidential print-ready payslip for an approved run; requires compensation view permission.
- `POST /payroll/runs/{runId}/lines/{lineId}/payslip/email` — sends the approved HTML payslip to the employee's HR email after confirmation. Requires `payroll.payslips.email`, compensation view permission and an enabled, non-development mail transport. Body: `{ request_key }` UUID; each intentional resend uses a new key.

Run creation accepts `{ request_key, period, branch_id, currency }` for single-currency payroll and adds `payment_date` for mixed runs; the UUID request key makes retries idempotent. Calculation lines retain an immutable snapshot of salary terms, FX and computed amounts. Single-currency posting uses the payroll expense, net wages payable, PAYE/AIDS payable, NSSA payable and other payroll deductions payable account mappings.
